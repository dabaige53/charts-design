# 看板位置引用与对话批注

> **当前状态（2026-11-10）**
> React 页面通过 `runtime-ui/src/position-comments.tsx` 实现位置批注，沿用 `manifest.annotations` 与 `dashboard_annotations`。本轮已构建打包并通过源码诊断，未运行 UI 测试、浏览器自动化或截图验收。

点击工具栏“添加位置批注”（或按 C），再点击页面元素或拖动框选区域，在位置旁输入并提交。提交后保留编号标记，并继续等待下一次选点；支持 Cmd/Ctrl+Enter。编号和列表可打开正文、回复、修改、重新标记、删除以及解决状态。旧备注保留在列表，可重新指定位置。

选区使用组件 ID、文字引文和相对坐标，不保存 DOM 对象。标记随滚动、尺寸变化及组件移动更新；位置无法匹配时，保留内容并提示重新标记。面板挂在页面顶层，手机窗口使用底部面板。保存期间阻止重复操作，失败保留选区与正文；未提交正文和回复按项目、看板保存在当前标签页的 sessionStorage 中。批注活动期间暂停报表自动刷新，退出后恢复图表交互；有草稿时提供继续入口。

项目模式提交前读取最新列表，使用 `dashboard_patch` 的 `expectedRevision` 与 `expectedAnnotations` 比对。只替换批注，不递增设计版本、不发布设计草稿、不创建布局检查点。并发修改冲突会显示错误，并保留当前输入。旧集中存储仍使用其原有版本行为。

本轮尚未接入宿主“附到对话”扩展、Agent 自动通知以及离线导出的编号显示；下文这些相关要求仍是后续规范，不能视为本轮已交付能力。

本轮应用资源标识：`28876b5a6a734f9b`。已执行应用构建与 `package:runtime`；impeccable 静态设计扫描无发现，Pyright 与 typescript-language-server 复查的 6 个文件均为 passed、无诊断。未运行 UI 测试。独立本机预览使用 8770 端口及复制的示例数据；原 8769 服务未重启。旧服务未声明独立保存能力时，新界面会提示重启并保留输入，不尝试按旧版方式保存。

批注面板按标题与状态、操作栏、正文、回复区分层。修改、重新标记与删除使用 Lucide 无边框图标，悬停或键盘聚焦显示操作名称；删除仅在交互时显示危险色。位置信息使用小号次要文字，正文保持正常字重。回复区独立留在面板底部，输入框有完整边界，提交按钮靠右；长正文在中间区域滚动。已解决状态显示说明并提供重新打开。新建正文和回复均支持 Cmd/Ctrl+Enter，并避开中文输入法的确认按键。

位置批注有两种方式：支持宿主扩展时附到对话；不支持扩展的客户端和独立网页保存页面批注。编辑模式不提供旧版全局、页面或图表批注按钮。查看模式保留位置批注能力，已有批注数据与读取工具继续保留。

## 附到宿主对话

MCP 客户端同时声明 `experimental["openai/modelContext"]` 和 `updateModelContext.text` 时，位置批注提供正文输入框和“附到对话”按钮。用户选中元素或拖选区域，填写批注后点击“附到对话”，位置和正文附到宿主输入框；用户之后自行发送对话。

每个引用包含项目路径、看板 ID、版本、组件 ID、选区、选中文本、筛选条件，以及已有批注的正文。连续附加保留之前的引用。客户端通过 `openai/modelContext` 通知移除时，同步当前附件。已有批注仍可打开并附到对话。

提交成功后关闭输入面板、清除当前选区，并保持批注模式，用户可继续选择下一个位置。提交失败保留正文与选区供重试。Esc 或“退出批注”退出模式。批注期间暂停页面报表自动刷新，避免打断输入；退出后恢复图表交互。独立的界面版本检查只显示更新提示。

在宿主客户端初始化时保留厂商 experimental 字段与标准能力校验；只有宿主明确声明能力时才显示“附到对话”。


协议定义见 [MCP 扩展规范](https://github.com/openai/mcp-extensions/blob/main/docs/spec.md#uiupdate-model-context-extensions)。

## 页面批注与存储

不支持上述扩展的客户端和独立网页使用页面保存：在查看模式点击“批注”，选择元素或区域，输入并保存，支持 Cmd/Ctrl+Enter。编号标记打开已有批注，列表支持跳转、修改与删除。离线 HTML 只能查看已有批注，不保存修改。批注不提供样式调整。

当前列表按未解决、已解决和全部筛选，显示关联位置和正文摘要。打开已有批注先显示正文和回复，点击“修改批注”进入编辑；取消不改写原文。桌面在位置旁显示面板，小于 640px 的窗口使用底部面板。

批注可标记已解决或重新打开；已解决批注不能继续回复。当前面板直接提供删除操作，尚未提供 Agent 请求按钮。保存期间显示进度并暂停重复操作；失败保留输入，页面重新挂载后可恢复未保存的正文或回复草稿。

保存的批注在文档中表示为 `manifest.annotations`，每项包含 `id`、`componentId`（页面批注为 `null`）、`text` 和 `createdAt`。`set_annotations` 整体替换列表，最多 100 条，每条正文最多 4000 字；修改受版本检查约束。

位置字段 `anchor` 可包含：

- `scope`：component、text 或 page。
- `kind`：element 或 area。
- `quote`：最多 1000 字的选中文本。
- `rect`：相对目标的 x、y、width、height，取值 0–1。
- `occurrence`：文字引文重复时，从 0 开始的匹配序号。

报告图表也暴露组件 ID，位置随图表移动与尺寸变化。文字通过引文匹配；引文改变或组件移除后，列表保留内容并显示位置失效。跨组件区域绑定页面相对位置，页面结构变化可能使区域偏移。引文和坐标不是截图，定位不明确时需检查实际页面。

项目模式的批注独立保存，不随设计恢复回退；旧集中存储沿用其历史版本行为。JSON 导出保留已有批注。修改看板时保留原批注，除非用户明确要求修改或删除。

## Agent 读取并处理批注

用户在对话中要求读取或按批注修改时，调用 `dashboard_annotations`，每次传入 `projectRoot` 和 `dashboardId`。结果包含当前版本、原始批注与锚点，以及按批注 ID 索引的目标标题、类型和配置位置；不读取图表明细或生成图表。组件已删除时返回 `componentExists: false`。`dashboard_get` 摘要的 `annotationCount` 可用于发现已有批注。

根据批注 ID 和 componentId 定位，读取当前文档后，按共享交付流程开始编辑批次、使用最新 `expectedRevision` 修改、完成检查，再预览一次。附到对话的引用由用户发送后处理；保存页面批注本身不会自动触发 Agent。

## 页面生命周期与检查


`runtime_info` 提供进程、项目、运行目录和前后端构建标识；“运行诊断”显示页面与服务版本及实际批注模式。安装更新和重连步骤统一见 [本地 MCP 更新](local-mcp-update.md)。

批注数据模型与锚点校验通过后端单元测试保护；新前端接入后将重新连接宿主能力测试与页面生命周期检查。维护时机：宿主扩展、批注字段、保存方式或页面生命周期变化时更新本文。
