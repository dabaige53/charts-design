# Charts Design 产品上下文

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

主要搭建者是经营分析师。分析师通过 Agent 调用本项目 MCP，创建和维护经营看板及分析报告。

主要阅读者是高管和业务人员。他们查看指标、筛选数据、比较业务表现，并结合指标说明和明细理解结果。

## Product Purpose

将业务数据、指标定义和分析组件组织为可查看、可交互、可维护的经营分析成果。

产品面向通用经营分析。航空是示例行业，不限定产品的用户、术语、数据结构或业务规则。

交付需要让阅读者能够理解数值含义、查看来源，并在筛选后看到相关组件一致更新。

## Positioning

以本项目 MCP 为生成和维护入口，将数据资产、指标定义、图表声明、看板布局和分析报告连接在同一工作流程中。

组件通过稳定声明和数据绑定参与分析；Agent 的修改进入项目资产和版本管理，再由应用展示。

## Operating Context

- 分析师提出分析需求，由 Agent 调用本项目 MCP 生成看板并查看效果。
- 经营看板与分析报告是两条生成路径，共用底层数据和指标定义。
- 阅读者在 Web 界面或 MCP 宿主中查看结果，使用筛选、图表联动、粒度切换、明细和指标说明。
- 看板编辑、批注、保存、检查点和恢复沿用项目已有流程。
- 组件画布与设计系统用于维护可复用组件，业务看板使用真实运行组件。

介绍页和展示页的制作方式尚未设定。本次确认的是通过本项目 MCP 生成和查看分析成果的使用流程。

## Capabilities and Constraints

- 图表支持内置预设、完整原生 ECharts 和 HTML/CSS/JavaScript 自由组件。执行边界和数据绑定范围见 [自由组件说明](../implementation/echarts-options.md)。
- KPI 不允许添加副标题、描述或解读段落；只展示指标名称、数值、单位、比较值及必要图形。业务定义放详情，分析内容放独立文本组件。

- 看板包含筛选器、指标卡、图表、数据表和说明；现有组件范围见 [UI 组件清单](../implementation/ui-component-inventory.md)。
- 数据资产和版本持久化由 Runtime 管理。COS 项目的网页通过共享查询 worker 处理授权数据；展示组件接收结果与事件，不各自实现指标算法。MCP 保留服务端查询能力。
- 筛选、分页、排序及粒度属于查看状态，不隐式改写已保存的看板定义。
- 项目数据、稳定组件 ID、版本检查、批次修改和检查点需要保留。
- MCP 升级必须适配已有看板和报告，延续原项目、看板标识、版本编号、历史与发布状态。升级本身不创建业务版本，不要求重新生成或整体重做已有成果。
- MCP 升级必须保留已有在线只读链接、在线编辑链接和独立分享链接的完整地址、访问凭据及原有效期。接口、渲染和存储变化由兼容适配承接，不以重建看板、重新签发链接或替换分享作为升级步骤；正常到期和用户明确要求的撤销仍按原规则执行。
- 腾讯云在线分享采用独立私有副本和 8 位数字访问密钥，支持不过期、7 天和 30 天；到期由云端 SCF 删除副本及访问记录，保留项目原稿。实现与部署条件见 [云端分享与清理](../operations/self-hosted-server.md#腾讯云在线分享与云端清理)。
- 设计资产与应用代码分开维护。应用资源构建、MCP 资源打包与画布更新是独立步骤。
- 区分真实数据、示例数据和设计预览数据；指标定义来自当前业务绑定。

### 产品强约束与选型自由

- 真实成果不编造业务数值、目标、基期或指标定义；来源和示例数据要能区分，未知规则保留待确认状态。
- 每个图表声明实际可用的渲染入口。未注册预设不能冒充可运行组件；需要库外图形时使用自由入口。
- KPI 不得通过 subtitle、description、desc、note、detail、rankSub、trendLabel 或 gaugeSub 塞入说明；定义和分析使用各自负责的展示位置。
- KPI 形态数量、mc16 使用数量、图表推荐和布局模板均为选型建议，不设生成配额。双轴不是全产品禁用项，图表预设不是形态上限。

## Brand Commitments

产品名称为 Charts Design，项目标识为 `charts-design`。

产品说明默认使用简体中文。业务名称、指标、单位和计算含义需要准确，同一概念保持称呼一致。

已有视觉约定维护在设计系统和组件规范中，本文件不另建配色、排版或组件样式规则。

## Product Principles

1. 从分析问题出发组织指标、图表和明细，让阅读者理解结果并继续追问。
2. 通过本项目 MCP 生成和维护成果，保持声明、数据绑定与应用展示一致。
3. 业务含义优先。样式和交互调整保留指标定义、单位、比较基准与数据来源。
4. 通用能力与行业示例分开，避免把航空示例固化为产品限制。
5. 清楚区分实现、构建和实际使用确认，按真实状态描述产品能力。

维护时机：已确认的使用者、产品目标、强约束或能力目标改变时更新；实现状态与当次验证证据不在本文重复维护。
