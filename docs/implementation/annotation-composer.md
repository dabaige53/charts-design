# 看板与报告位置批注

## 入口与权限

编辑、预览和独立分享复用同一批注面板、稳定组件 ID 和报告文字锚点。内容的 `readOnly` 只限制布局、标题、数据定义和版本操作；批注由 `annotationAccess` 中的 `canRead`、`canAnnotate` 和 `canManageAnnotations` 独立控制，后端也分别鉴权。

| 页面 | 批注权限 |
| --- | --- |
| 本机或服务器作者编辑页 | 查看、新增与管理项目批注 |
| 本机预览页 | 查看与新增项目批注，不能修改内容或管理已有批注 |
| 服务器在线预览 | 按链接签发的批注权限处理；旧只读链接不自动获得写权限 |
| 独立分享 | “仅查看”不允许提交；“可批注”允许新增，不能修改内容、保存版本或发布 |
| 纯静态 ZIP、只读 HTML | 没有批注持久化接口时不显示可提交状态 |

本机普通浏览器入口由 `serve --dashboard <id>` 返回，预览无需公网。stdio `dashboard_preview` 返回 `browserLinks`，MCP 宿主中的“在浏览器中批注”打开 `viewUrl`；批注不会通过 MCP 读取或提交。启动与链接约定见 [Runtime 入口](dashboard-runtime.md#启动与依赖)。当前没有宿主“附到对话”扩展、Agent 自动通知或批注同步进程。

## 位置选取与面板

具备新增权限时，点击工具栏“添加位置批注”（或按 C），再点击页面元素或拖动框选区域，在位置旁输入并提交；支持 Cmd/Ctrl+Enter，并避开中文输入法的确认按键。提交后保留编号标记，可以继续选点。没有新增权限时，入口只用于查看已有批注。

进入批注后，工具栏入口显示按下状态，可选取区域显示十字光标。查看详情或列表时暂停选取，修改或重新标记时恢复选取。Esc、顶部入口和“退出批注”都会结束批注模式，隐藏编号、选区、详情、列表和底部工具条；普通浏览页面不显示批注细节。

面板按状态、操作栏、正文和回复区分层；桌面在位置旁显示，小于 640px 的窗口使用底部面板。列表支持未解决、已解决和全部筛选，显示关联位置及正文摘要。仅具备管理权限的作者可以修改、回复、重新标记、删除、解决或重新打开批注；已解决条目不能继续回复。读者批注只提供新增与查看。

未提交正文、未确认保存的新增批注和作者回复按批注作用域、看板及权限保存在当前标签页的 sessionStorage 中；不同分享使用不同作用域。批注活动期间暂停报表自动刷新，退出后恢复图表交互与刷新。失败条目保留原 ID 和正文供重试，未取得保存回执时不提示成功。

工作区令牌和分享密钥只能证明持有访问权限。页面如实显示作者、访客或自填署名，并标明未经账户验证；HTTP 保存使用最多 80 字的自填署名，不信任客户端传入的账户验证标记。

## HTTP 保存与版本定位

`annotation-client.ts` 使用页面配置的同源 `annotationAccess.endpoint`，通过 GET 读取、POST 保存。面板内部保留原有回调名称以复用组件，实际请求不经过内容工具接口或 MCP。主要入口为：

| 场景 | 接口 |
| --- | --- |
| 本机项目 | `/api/annotations/<dashboardId>` |
| 服务器作者工作区 | `/api/v1/p/<project>/annotations/<dashboardId>` |
| 独立分享 | `/s/<shareId>/api/annotations` |

打开批注及批注模式下页面重新可见时按需读取列表，不定时轮询。GET 和 POST 都携带页面当前显示的 `revision`；工作区用该版本定位组件或报告段落，并把实际目标版本返回为 `targetRevision`。响应顶层 `revision` 是项目当前草稿修订，用于管理已有批注时的并发检查。比如页面显示保存版 A、草稿已到 B，新增批注记录 A 的位置上下文，列表管理仍检查 B；读取批注不会把页面切换成 B。

新增只发送 `append` 当前条目，服务端合并不同批注 ID，相同 ID 的成功请求重试返回原条目，不重复写事件。作者修改、删除或回复仍提交 `expectedAnnotations`、`annotations` 和当前 `expectedRevision` 做列表比对；并发冲突需要重新读取，不能强行覆盖。预览与分享读者不能调用列表管理。批注写入不生成内容版本、不重新编码 Parquet、不上传整页，也不改变分享指向的版本。

本机预览批注保存在本机项目；服务器工作区批注保存在原项目存储。分享批注独立保存在分享服务，作用域固定为分享 ID、发布版本和已有位置锚点，同版本的两个分享也不会混合批注。本机未公开批注不随发布外发；分享过期或撤销后原链接不能读取或提交批注。

作者从“版本与分享”的“分享”页签选择对应分享，点击“查看读者批注”按需读取并打开原发布版的只读反馈页。当前草稿即使移动或删除原组件，仍能在冻结副本定位；反馈不会自动合并到草稿或本机批注。发布引用、版本与数据位置见 [项目资产与加载](project-runtime.md#保存发布与恢复)。

## 锚点与持久存储

项目批注在读取文档中表示为 `manifest.annotations`，每项保留 `id`、`componentId`（页面或报告文字批注可为 `null`）、`text`、`createdAt`，以及已有作者、状态、回复和版本上下文字段。旧 `set_annotations` 列表替换入口继续兼容；最多 100 条，每条正文最多 4000 字。

位置字段 `anchor` 可包含：

- `scope`：component、text 或 page。
- `kind`：element 或 area。
- `quote`：最多 1000 字的选中文本。
- `rect`：相对目标的 x、y、width、height，取值 0–1。
- `occurrence`：文字引文重复时，从 0 开始的匹配序号。

选区不保存 DOM 对象。报告图表也暴露组件 ID，标记随滚动、尺寸变化及组件移动更新；文字通过引文匹配。引文改变或组件移除后，列表保留内容并显示位置失效，作者可重新标记。跨组件区域绑定页面相对位置，结构变化可能使区域偏移；引文和坐标不是截图，定位不明确时需核对原版本。

项目批注独立保存，不随设计恢复回退；旧集中存储沿用其历史版本行为。项目 JSON 导出保留已有批注，修改看板时保留原批注，除非用户明确要求修改或删除。只读 HTML 和静态 ZIP 移除本机批注及运行权限，包括 `browserLinks`、`annotationAccess` 和发布管理入口；没有独立批注后端的静态页面不能提交批注。

本地批注和事件先在 SQLite 事务中提交，再串行刷新批注镜像；文件写入期间释放数据库写锁。批注保存不刷新草稿、设计历史或检查点镜像，普通设计修改也不重写未改变的批注文件。批注事件历史完整保留，重试同一批注 ID 不增加事件。

数据库已提交但镜像写入失败时，重试相同新增批注 ID 会补齐镜像；列表替换仍保留原有比对约束，先读取最新列表，再提交同一列表也会刷新镜像，不追加事件。

## Agent 读取并处理批注

现有 Agent 工具继续兼容。用户在对话中明确要求读取项目批注或按批注修改时，可调用 `dashboard_annotations`，每次传入 `projectRoot` 和 `dashboardId`；它读取该项目的批注，不自动拉取分享反馈。结果包含当前草稿修订、原始批注与锚点，目标索引默认按当前草稿解析。已保存组件索引的页面还返回目标标题和类型；旧云端文档缺少索引时，`targetsResolved: false`，可从 `dashboard_get` 确认目标。只读取列表时传 `includeTargets: false`。

处理批注时先区分条目上下文中的原版本与当前草稿，再按批注 ID、组件 ID 或报告引文定位；按共享交付流程使用最新 `expectedRevision` 修改、完成检查并预览。兼容工具 `dashboard_annotations_update` 保留原有项目批注管理能力，网页批注保存和分享反馈读取不依赖这些 Agent 调用。

## 页面生命周期与检查

`runtime_info` 提供进程、项目、运行目录和前后端构建标识；“运行诊断”显示页面与服务版本及实际批注模式。安装更新和重连步骤统一见 [本地 MCP 更新](../operations/local-mcp-update.md)。

后端检查保护数据模型、锚点、版本与权限；浏览器操作、stdio 宿主入口和真实分享部署分别验证。维护时机：批注权限、字段、HTTP 保存方式或页面生命周期变化时更新本文。
