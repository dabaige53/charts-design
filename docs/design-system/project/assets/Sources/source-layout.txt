Elevation on MDS
Elevations represent different user interface layers simulated through the use of shadows. Placing different elements on
different layers creates a clear hierarchy of interface elements and makes it easier to locate currently available options for
the user. Layers are represented by various sized shadows to indicate a position along an imaginary z-axis extending
above the user interface towards the user.

Spacing
Spacing is one of the most important aspects of visual design and is foundational to the
McKinsey Design System. Underlying every layout, component or spatial relationship is a
4pt spacing system. We use spacing consistently and intentionally to establish order,
hierarchy and rhythm.




Spacing sizes and increments
All spacing helpers are percentages or multiples of 4px (0.25rem). Using 4px as a constant offers flexibility,
clean numbers to work with, and helps improve design and accessibility when fonts are scaled in a browser.
This also offers spacing consistency and consistent rhythm throughout the design system.

Spacing text
Space text to the direct selection of a text box in Sketch. Line height determines
text box size, so apply the correct line height to the text before making
measurements.

Avoid measuring to the baseline of text. That creates unexpected spacing results.

4pt grid system guidance
The 4pt grid system is the underlying fabric that provides consistency and structure to all
visual elements of McKinsey's Design System. It establishes a framework for consistently
scaling and evolving the design system in a predictable and flexible way over time. All
spacing, typography, and visual elements adhere to the 4pt grid system.




Getting started
The artboards you see here are setup with 4pt grid and layout settings in a variety of common
sizes used for designing responsive web applications. These can be used as is or as a starting
point for your projects. Typically Designers will choose three artboards representing mobile,
tablet and desktop. The 4pt grid is very flexible and you are encouraged to setup your artboard
to suit your needs using the grid system.




Need the grid setup for a specific device?
We have those too! We’ve worked to identify the most commonly used devices at the firm and
have setup artboards with all the grid and layout settings you need to get started. You can find
these on Box at:

Avatars
Avatars display a user’s profile image. In our case, we encapsulate the photo in a circle.
You may find these commonly used as a profile image in the top right of a header, on a
profile card, in text messages, and many other contexts.




Avatar sizes
Avatar size depends on the element where it lives. For example, use Huge (256px) for big components like
profile cards. On small components like a dashboard, it’s more appropriate to use the extra small (32px).
Notice, the smaller the circle gets, the more zoom you need on the photo to recognize the person.

Breadcrumbs
Breadcrumbs are used to help the users keep track and maintain awareness of the overall locations
within a specific navigation that the user is currently in. A breadcrumb must have the minimum size
of 2 items and the maximum of 5 items, so that it’s easier for the user to use it.




Anatomy

                 16 16




Breadcrumbs options
The last item on the breadcrumb is always where the user is currently on the overall navigation, so it uses the electric
blue to differentiate from the others.



2 items           Item 1        Active item




3 items           Item 1        Item 2        Active item




4 items           Item 1        Item 2        Item 3        Active item




5 items           Item 1        Item 2        Item 3        Item 4        Active item




Active item       Item 1        Item 2        Item 3        Item 4        Active item




If a breadcrumb needs more than 5 levels of navigation, our recommendation is to simply use the 16px glyphed icon ellipsis to
indicate that there is more hidden within it. Once the user clicks on it, a popup menu will appear, providing all the navigation
levels that are compressed. The best and appropriate place to put the ellipsis is replacing the second item on the
breadcrumb. By doing so the first level is always visible, keeping the reference where iit all started, and we keep the last 3
levels, where the user is mostly likely to use to navigate.

Cards
A card component creates a structure that contains different pieces of information. Cards are used to feature content and
are usually placed at an elevation of 2px to highlight their interactivity. Depending on the specific needs of the card and
the content the either the entire card or individual components may be active areas. When the whole card has a single
interaction with a mouse over, the component will be raised to the 8px elevation to emphasize the interaction.


Cards are used to group information about a specific subject. Two common examples include a profile with a lot of
information about the featured company/person or an article with a pertinent illustration/photo, eyebrow text, and
introductory text. Another very common use of cards are in dashboards, where each card my have a different content and
size, with all cards adjusted for their specific content. In this usage the cards adapt to a very flexible layout to provide
structure and focus to a lot of different information.


The expected behavior upon interacting with a card is to navigate to another page with more extensive content related to
the content that was summarized and featured on the selected card.




Specifications/Anatomy
The card is a flexible container component with content that will vary depending on individual use cases. Each part of the card shown below -
from the Image all the way down to the Call to action - are optional. The main card content may be replaced by other non-text components such
as a chart for a graphical dashboard requirement, but the pattern shown below should meet most text based content presentation needs. Use this
component as the initial starting point when creating cards and simplify the card by removing unneeded items.

Minimum and maximum text sizes
To keep cards consistent with each other and to have good visual proportions, the minimum, maximum, and recommended lines of text are
defined for the card titles and texts. For titles the minimum is 1 line and the maximum is 3 lines with a recommendation for 2 lines of text. For the
card's main content the minimum is 2 lines and the maximum 5 lines with a recommendation of either 3 or 4 lines of text.The main text for a card
should be a short summary, general idea, or introductory text that informs and guides the user to the detailed content.

Matching cards
Although card dimensions may vary a lot depending on the content they have, the general rule is to match the size of other nearby cards - for
example, matching the height and width of cards in the same row and column. This will reinforce a grid structure and help the user identify and
categorize the content into imaginary boxes for quick scanning and focus. The 16px spacing between the call to action and the penultimate
content should be considered the minimum and allowed to vary depending on the height of the card as dictated by other nearby cards and the
height of the card's content.

component is usually not visible when the form first loads and appears after the user clicks on a date or date range input
field. The user then selects a specific date instead of inputing the information with the keyboard. The expanded date
picker provides additional information on date restrictions and eliminates confusion between international date format
variations by spelling out or abbreviating the month and including a four digit year.

Modals
A modal is a content container that floats above a main page layout and it is triggered by a click event on that page. When
active, it blocks all other page interactions, allowing users to focus on smaller pieces of critical content or perform an
activity that requires their full attention. Modals are invasive to the user's workflow as they block all other content and
allows them to focus on a single task. A deep blue layer (#051C2C) with 85% opacity stands between the page and the
modal and can be dismissed by selecting the close (X) icon, a CTA (e.g. Cancel, Submit) and in some instances depending
on the context, by clicking anywhere on the opacity layer layer.

A modal is made up of 3 sections, the top section, the content section and the bottom section. All sections are optional and should be determined
by the needs of the solution.

The Top Section may contain a representative icon to help communicate the message or give a sense of status or urgency to the action being
requested. The top section also include an "X" icon to dismiss the modal. The graphic is not always required but recommended.

The Content Section contains a title, text, data visualizations, input fields, and any other variety of media, including photos, graphics or illustrations.
All content should be written succinctly and objectively so that it occupies as few lines as possible.

The Bottom Section contains action items including links and buttons to proceed. Typical combinations may include Cancel | Delete | Save |
Send.

Modals can have many different sizes but must always maintain the 40px padding on the top and bottom margins and should never consume more
than 50% of a screen.

On mobile viewports, modals typically take up more space and have larger CTAs to make them tap friendly.

Status badge

Status badges are slightly larger than regular numeric value badges and highlight an item’s status in a specific context. They are commonly used in tables depicting a list of items
and each of their statuses. In scenarios where a lot of status tags are used, we suggest the use of the lighter version. In scenarios where they are used with more spacing
between them, the default version will be more prominent.



  Default version            Light version                 Usage                           Common labels


       In progress            In progress                  Items in progress               In progress, Open, Modified


        Default                 Default                    General status                  To do, Unavailable, Minor, Not Started


        Sucess                  Sucess                     Successful items                Available, Done, Approved, Resolved, Added


          Error                  Error                     Error or removed items          Errors, Declined, Failed, Removed, Critical


        Warning                Warning                     Attention required items        Busy, Blocked, Missing, Warning

Tag
Tags are used as UI labels that easily differentiate between different options. Depending on the variation, they can feature fast interactions for selecting, adding, and removing
options with ease. They can be used in different scenarios: such as an alternative for checkboxes or more commonly, within a multi-select input field.
