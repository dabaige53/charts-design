# MCP 优化交付记录

## 已实现

- MCP 启动器显式指定包的 Python 模块搜索位置，保持 cwd 不变，使项目相对路径继续有效。
- `runtime_info` 返回 `backendBuildId` 与 `moduleRoot`。后端身份在进程启动时记录，Doctor 缓存必须同时匹配设计、数据、UI 和后端版本。
- `dashboard_patch`、`dashboard_edit_finish`、`dashboard_checkpoint` 和 `dashboard_history_diff` 返回 `semanticChanges`。覆盖组件增删、数据引用、指标、比较绑定、定义、展示编码和筛选；输出字段路径及变更类型，不输出业务数据。批次完成对比当前已发布检查点与草稿；最多返回 200 项并标识是否截断。差异用于复核，不阻断已授权的正常删除。
- 页面工具请求共用最多 4 个并发槽，分块读取也计入。避免多个组件各自开 4 路而叠加。
- 新页面的渐进图表查询声明 `compactRecords`，将重复字段名按列编码；浏览器无损恢复后使用原渲染器。旧调用默认返回原格式。表格继续使用独立分页查询，导出仍保留完整数据。此阶段没有引入散点抽样或改变业务汇总。
