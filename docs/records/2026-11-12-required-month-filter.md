# 必选月份筛选恢复修复

日期：2026-11-12，时区 Asia/Shanghai。问题标识：`required-month-20261112`。

## 根因与引入位置

2026-11-10 的 React 界面接入提交 `1842436` 中，运行状态重置将所有筛选值清空，选择控件与生效条件标签也未读取 `required`。已有的 `clearFilterValues` 必选保留逻辑未被新运行状态使用。

2026-11-12 的 COS 浏览器读取接入提交 `e0466a1` 将候选项请求转入共享分片客户端，并显式传入 `filters=[]`。该客户端先执行必选分区校验，再将请求交给区分候选项和数据查询的引擎。因此候选项请求在读取候选文件前就报“必须选择一项”。MCP 的候选项接口不经过浏览器分片客户端。

这两处行为组合后，用户清空必选月份会使图表报错，同时无法加载候选月份恢复。服务端候选接口仍能返回月份，不支持将该问题归因为业务数据缺失。

## 修复范围

- 浏览器候选项请求独立于必选分区校验，不改变当前数据分区或重启其 Worker。
- 运行状态拒绝将必选选择条件设为空值或多值，重置全部复用必选保留逻辑。
- 必选下拉禁用清空，生效条件保留标签但隐藏移除按钮。已有空状态显示“请选择”并允许重新选择。
- 实际数据查询仍拒绝空月份、多月份和范围条件。
- 未修改业务看板、数据、指标定义或布局。
