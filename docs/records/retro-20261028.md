## 尚需优化的 MCP 项

|优先级|证据与影响|建议动作及完成条件|
|---|---|---|
|高|`bin/mcp-runtime.js` 启动 Python 模块时继承 cwd。性能对照首次试跑因此加载源码目录，而非指定安装包，试跑结果已排除。|固定模块导入来源，同时保留项目相对路径语义；增加不同 cwd 下加载同一安装包的回归检查。|
|高|`service.py` 状态返回 UI build ID；Doctor 缓存也以 UI build ID 等判断有效性。后端代码变化可不改变 UI ID。|增加后端构建标识及实际模块来源；Doctor 缓存纳入后端身份。能区分源码、安装包与连接中的旧进程。|
|高|本次迁移曾保留外观但丢失 KPI 对比绑定和完整定义。现有流程说明已改，尚缺机械保护。|增加迁移前后语义差异报告，列出删除的绑定、基期和解释，由调用方明确接受；为聚合比率、缺失/零基期和筛选后的比较补回归覆盖。|
|中|性能记录中单组件约 258 KB。`web/tool-result.mjs` 每个响应独立允许 4 个分块请求，多组件同时查询会叠加并发。|使用页面级请求队列；图表聚合查询与全量表格/导出分离。保留正确总量，不以截断明细换速度。|
|中|筛选缓存改善重复访问；首次构建缓存仍有成本。现有指标不足以完整解释用户等待。|分别记录筛选选项、缓存命中、查询、分块、应用结果及实际渲染耗时；按请求编号串联，避免记录业务明细。|
|中|现有性能证据来自官方 AppBridge 测试宿主，而非 Codex 侧栏。|在实际宿主核对首屏、筛选、空结果、提示框和连续切换；单独记录验收状态。|
