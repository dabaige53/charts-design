# 2026-11-26 Runtime 性能与交付改造

本轮针对版本读取混用、重复校验与镜像写入、全量 JSON 数据交付、网页重复分组和表格翻页计算开展源码改造。保留单个 MCP、现有 React 页面和 SQLite/PostgreSQL 事务入口，把有明确收益的数据编码与回读交给 Rust。未部署线上服务、未发布原生程序标签、未迁移或删除真实项目数据。

基线为 `0b77d0cadf429da49b852c1701cd1f45cd353374`。所有测量使用合成数据；[原始记录](2026-11-26-runtime-performance.json)保存样本、范围、环境、源码哈希和验证结果。完整 CI 与跨平台结果以对应 PR 的 Actions 为准，本记录区分已经完成的本地证据与尚需发布的交付动作。

## 已完成的边界

| 对象 | 实现 | 保持的约束 |
| --- | --- | --- |
| 编辑与评论 | 草稿、批注、检查点镜像按变更范围同步；文件锁与原子替换；批注写入重试修复镜像 | 数据库先提交，评论不推进设计版本，设计恢复不撤回评论 |
| 保存与阅读 | 统一读取版本选择，图表、明细、候选项、口径、来源、CSV 与快照导出携带同一 revision/dataVersion；状态使用一致性读取快照 | 保存版和未保存草稿分别可读，过时请求明确拒绝，历史固定读取入口保留 |
| 数据编码 | Rust 只读 SQLite，输出 Parquet 行分片、分区原始序号及单列候选项；SQLite 执行高基数去重 | 原始行、字段顺序、类型、null/缺失、分区剪枝和现有指标公式 |
| 云端包与分享 | 新 COS 包使用 Parquet；新分享直接复用新包，旧包生成分享专属的 Parquet；沿用登记、鉴权和清理协议 | 旧包、旧分享保持可读；不存在脱离引用管理的公共业务缓存；未改线上 schema |
| 静态网页 | 包含 UI、Worker 和实际数据文件，可放到普通静态 HTTP 服务；编码和公共 UI 压缩模板分别复用 | 无 MCP、Python、Rust、数据库、CDN、Wasm 或 Range 服务依赖 |
| 网页查询 | 按语义复用分组统计；缓存有预算且不保存分组行数组；计算列按需延后到当前页，翻页复用排序结果 | 搜索、按派生列排序和完整 CSV 仍处理完整范围；输出页与内部缓存隔离 |
| 本地安装 | 固定版本预编译安装器，SHA-256 与实际版本检查后原子替换；源码构建使用相同发现目录 | 安装失败保留旧程序，不在 MCP 请求中下载或编译；原生发布与服务部署分别触发 |

Python JSON 行编码和全字段候选值字典已从新 COS 包写入路径移除。配置、版本声明、少量计算结果和回执仍使用 JSON；旧 PostgreSQL 项目与上传暂存协议没有被自动迁移。对于同一旧 JSON 数据包，不同新分享仍各自保存一份 Parquet 副本，同次多页与本机编码可复用。跨分享长期去重需要先扩展正式对象登记和清理协议，当前实现没有绕过既有唯一索引。

## 性能证据

主要环境为 Linux x86_64、Xeon Platinum 8573C、9 个可见逻辑 CPU、约 10 GB 主机内存、Python 3.11.16、Bun 1.3.8、Rust 1.91.1。共享执行主机、JIT、GC 与文件系统缓存会造成波动；没有把应用缓存未命中等同于物理磁盘冷启动。

| 测量对象 | 改造前 | 改造后 | 范围 |
| --- | ---: | ---: | --- |
| Doctor，60 组件、2,400 行与较大定义/批注 | 144.904 ms | 10.396 ms | 各 7 次预热后中位数，包含检查与诊断写入 |
| 100 万行主数据文件生成 | 17.749 s | 2.168 s | 各 3 次中位数，gzip JSON 对比最终数字编码的 Parquet；不含导入、UI、ZIP |
| 同一主数据文件体积 | 9,644,755 B | 1,810,023 B | 减少约 81.2%；不含候选项、查询 SQLite、网页资源或云账单 |
| Parquet 编码缓存命中 | — | 14.18 ms | 3 次中位数，仍复制文件并核对 SHA-256 |
| 100 万行、24 个共享分组图表 | 2,772.149 ms | 455.197 ms | 最终配对复测，各 3 次中位数，已解码数据，独立 Bun 进程 |
| 100 万行计算列表格首屏，10 行 | 399.433 ms | 3.248 ms | 最终表格序列的单次观测，延后无关的全表计算 |
| 表格首次排序 | 1,873.596 ms | 1,801.004 ms | 仍需排序全部行，没有将这一成本隐藏到翻页 |
| 相同排序后的下一页 | 1,749.036 ms | 0.202 ms | 复用完整排序范围，只隔离与计算返回页 |
| 表格序列峰值 RSS | 462.508 MiB | 211.453 MiB | 仅该计算列表格序列，不能推广到所有看板 |
| 10 万行看板重复 ZIP 导出 | 355.943 ms | 35.524 ms | UI 模板缓存阶段的一次前后观测，不代表网络或生产 SLA |

最终网页基准使用相同脚本、明确基线、分别启动的 Bun 进程，并记录当前源码 SHA-256。早期探索曾观察到更大的耗时差距，正式对外使用上表的最终复测。分组查询峰值 RSS 为 538.863 → 571.125 MiB，没有下降；因此不宣称所有查询都降低了峰值内存。无排序的第二页为 0.086 → 0.406 ms，新增返回页隔离有小幅开销，仍低于 1 ms。完整原始值保留在 JSON 记录中。

性能改进有工作量证据支撑：2 万行、24 图表的探针中，分组字段读取从 480,000 次降到 40,000 次，数值字段从 320,000 次降到 20,000 次。Doctor 组件阶段的整文档深复制从 60 次降到 0 次，完整定义编码从 60 次降到 1 次；该阶段累计编码字节从 16,015,977 降到 283,806。完整定义和 16 MiB 响应边界继续检查。

没有直接接受默认 Parquet 编码：首次实现虽然生成更快，文件却达到 13,151,172 B，大于原 gzip JSON。Int64 使用 delta 编码、Float64 使用 byte-stream-split 后降至 1,810,023 B；代价是编码中位数从约 1.16 s 增到 2.17 s。最终选择减少传输和重复分享体积，同时仍明显快于原 JSON 编码。

最终 Linux 程序为 11,475,688 B，包含实际 Parquet 回读校验；运行镜像不携带 Rust 工具链。最终 Worker 为 80,313 B，gzip 后 26,120 B，比同工具重建的原 Worker 增加 20,628 B。页面仍将分片解码为行对象，优化来自去掉重复工作，没有声称获得浏览器列式 SQL 扫描能力。

## 验证与复现

真实跨语言检查从 Python SQLite 导入开始，经 Rust Parquet 写出、网页读取器和实际打包 Worker，核对类型、中文字段、整数边界、显式 null 与缺失字段、分区行序、候选项、比率、搜索、分页和 CSV。百万行记录逐行核对顺序并核对总额及缺失/null 计数，没有把 writer 回执当作内容正确性的唯一依据。

普通 Python 静态 HTTP 服务在 `/site/` 子路径提供网页资源，六个入口资源均返回 200；实际打包 Worker 通过 HTTP 读取 10 万行数据，收入总额 124,987,500、总记录数和最后一行均正确。未启动 Charts MCP 或 API 服务，也没有执行浏览器视觉验收。容器 smoke 已增加从下载 ZIP 执行其中的 Worker、逐行对比原样例数据的 gate；同一 harness 已本地执行通过，实际容器由 CI 验证。

版本用例通过真实 stdio MCP，把保存版设置为 30 CNY、草稿设置为 900 USD，逐项检查所有读取面使用相同修订；同时用实际 SQLite 写入交错验证状态读取不会拼接不同事务。云边界用例使用内存对象存储，原生写出和 Worker 查询真实执行，覆盖冷缓存恢复、混合格式多页分享、失败重试、授权、MIME、迁移前实际解码、只删除分享自己的文件。没有把这些结果表述为真实云端部署验收。

新增或直接相关检查包括：Rust 9 项、跨语言静态数据 5 项、静态查询/缓存 17 项、部署包 7 项、COS 11 个不同用例、读取版本网页交互、MCP 收据和版本并发，以及类型、Ruff、安装器、文档和构建检查。另以固定种子比较 40 个合成场景、每个 9 个查询，360 个新旧结果一致。完整 Python/Bun/React 回归、覆盖率、容器和五个平台的 native 包检查交给 PR CI，不在本地重复整套。
