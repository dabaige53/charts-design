# 急转看板筛选加载问题盘点

日期：2026-11-12，时区 Asia/Shanghai。状态：待测量与修复，本次不修改运行代码。

## 用户问题与处理范围

急转看板打开筛选器后，需要等待较长时间才出现候选条件；切换月份后，数据加载也慢。用户要求仔细比较筛选器与预览的加载路径，先盘点、提交记录，后续修复。

这两个等待阶段分开处理：候选条件出现慢，不等同于选定月份后图表计算慢。COS 存储、按月分片、浏览器缓存和页面实际使用的程序版本也必须分别确认。

后续修复遵循[升级兼容要求](../operations/local-mcp-update.md#升级兼容要求)：沿用原 URL、访问凭据、业务版本、数据与布局，不通过重建看板或替换分享完成平台升级。

## 加载路径对比

| 环节 | MCP 预览路径 | COS 网页及独立分享路径 | 需要核对的差异 |
| --- | --- | --- | --- |
| 候选项来源 | `LocalView.filter_options` 将消费者数据引用交给 `option_page` 查询 | `createStaticQuery` 读取各数据集的字段选项索引，再合并、搜索、排序和分页 | 不能用 MCP 候选接口快证明浏览器下拉快 |
| 候选项预加载 | `service.py` 仅在非 COS 项目分支按 `preloadFilterIds` 预加载并缓存 | COS 不执行该预加载分支；前端另读选项文件 | 需确认返回文档是否已有候选项，以及控件是否实际使用 |
| 下拉首次展开 | 共享 `SelectionFilter` 总是提供异步加载函数 | 使用同一共享控件 | 两者均有 150 毫秒等待；耗时差异还取决于后续查询路径 |
| 图表数据 | MCP 服务端查询并返回计算结果 | 浏览器读取数据分片后在 Worker 中计算 | 网络传输、解压与本地计算成本不同 |
| 月份切换 | 服务端继续处理新的筛选请求 | 必选分区值变化时终止旧 Worker，再创建新 Worker | 浏览器已读取数据及选项的内存缓存不延续 |
| 分享文件访问 | 不经过独立分享文件网关 | 每个文件经会话及分享有效性检查，再读取 COS 内容 | COS 存储不意味着浏览器直接从 COS 下载 |

源码入口：[共享筛选控件](../../runtime-ui/src/controls.tsx)、[筛选器绑定](../../runtime-ui/src/dashboard.tsx)、[MCP 服务](../../dashboard_runtime/service.py)、[本地视图](../../dashboard_runtime/local_view.py)、[COS 网页适配](../../runtime-ui/src/cos-client.ts)、[独立分享适配](../../runtime-ui/src/static.tsx)。

| FL-05 | 高 | 必选月份变化会销毁旧 Worker，清除其文件、候选项和计算缓存；小范围复现已确认切回原月再次读取文件 | 月份往返切换重复加载；切月后下拉也可能重新读取索引 | 验证月份往返、快速连切和切月时打开下拉；同时检查旧结果不覆盖新选择、内存可控 |
| FL-06 | 高 | 分享文件响应为 `private, no-store, max-age=0`；每次访问先读取控制记录，云端启用时查询 `share_access`，资产引用路径还查询 `object_get` 后读取内容 | 内存缓存丢失后，不能依赖浏览器 HTTP 缓存减少文件请求；小索引也承担网关往返 | 拆分控制记录、权限查询、对象元信息、COS 读取及传输时间。不能直接取消鉴权或改变到期、撤销规则 |

## 小范围复现

使用当前源码的 `createStaticClient` 和 `createStaticQuery`，以进程内 Worker 替身及两个单行月份分片运行“10月 → 9月 → 10月”，每次数据查询后读取月份候选。

| 观察项 | 结果 |
| --- | --- |
| 文件读取顺序 | `oct → months → sep → months → oct → months` |
| 10 月分片读取次数 | 2 |
| 月份索引读取次数 | 3 |

复现确认客户端切月后无法复用原 Worker 的文件缓存。它没有真实网络、浏览器线程或 COS 请求，不能作为线上耗时、浏览器性能或修复成功的证据。

## 后续测量与修复验收

在同一设备、网络、业务版本、默认月份和筛选条件下，对比 MCP 预览、在线页面及用户原独立分享。先匹配入口；首次打开与已缓存场景分开记录。

逐一登记月份、机场、中转类型、航班号、风险等级、流程节点、事件分类等实际存在的筛选器。区分选择列表与文本搜索，不把文本输入当成需要下载候选列表的控件。每项至少记录：

1. 从展开到首批可选条件出现的时间，以及选项是否完整、能否搜索和翻页。
2. 候选请求等待队列、网络首字节、下载、解压、合并和排序的时间。
3. 索引文件数、数据分片数、实际传输字节及内存缓存命中；月份选择器是否意外读取业务行。
4. 首次展开、关闭重开、图表加载中展开、切月后展开、跨页展开的差异。
5. 月份首次切换、切回已访问月份和快速连续切换时，各组件完成时间、重复请求与内存变化。

根据测量确认主因，再选择修复方式。当前不预设并发增量、长期缓存或 CDN 方案，也不将删除鉴权作为优化。性能目标待基线测量后确定；修复应验证候选完整性、筛选语义、旧请求隔离、分享撤销与到期行为，以及原链接和业务版本连续性。
