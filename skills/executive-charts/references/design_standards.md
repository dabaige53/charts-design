# 看板设计规范

页面使用淡灰底与白色卡片。具体变量、字阶和组件尺寸维护在 [产品设计系统](../../../docs/reference/DESIGN.md)。本页负责组合与阅读规则。

## 按问题与证据选图

先写清每张图帮助读者判断什么，再选择形态。向 `chart_recommend` 提供已知类别数、指标数、时间字段；需要筛选重算时设 `requiresFilterBinding: true`。核对候选的 `requirements`、`cautions`、`bindingMode` 与整体 `designGuidance`，再用 `chart_declarations.codes` 批量取得所选声明。未知条件保持未知，返回的 `questions` 先从现有来源核实。推荐分数与合成示例均不证明当前数据满足统计或业务条件。

| 读者的问题 | 优先考虑 | 需要的证据与取舍 |
| --- | --- | --- |
| 哪个类别更大，差距多少 | 柱形、横向条形；同指标多组比较用小多图 | 柱条从零起；长名称用横向条形。类别过多先按问题分组或排名，展示 Top N 时写明范围并保留其余明细。 |
| 随时间如何变化 | 折线；离散阶跃用阶梯线 | 时间按真实顺序与粒度排列；缺失不是零，不用平滑曲线制造未观测的波动。多序列拥挤时用同尺度小多图。 |
| 两期差异或排名如何变化 | 哑铃、斜率、并列柱形 | 两期对象、单位和统计范围一致；百分比变化与百分点分开。独立指标并不天然构成“前后”两期。 |
| 是否达到目标 | 子弹图、实际与目标对比；单指标用目标卡 | 真实目标、实际与阈值要同口径；没有目标证据时展示数值或趋势。阈值不能按视觉效果编造。 |
| 总量由哪些部分构成 | 堆叠条形；少量互斥部分可用环形 | 部分可相加且分母明确；比较比例用 100% 堆叠并保留总量。负值、重叠类别或非完整分母不使用饼图。 |
| 数值如何分布，有无异常 | 直方图、箱线图、密度图 | 需要原始观测或经核对的分布统计；交代样本量、分箱/四分位口径。类别均值不能冒充观测分布。 |
| 两个量是否相关 | 散点；第三个量确需表达时用气泡 | x/y 来自同一观察对象，面积编码非负规模，单位清楚；相关不推出因果。双轴用于有明确关联的不同单位序列，保留两轴标签并避免制造虚假同步。 |
| 在哪些环节流失、流向何处 | 漏斗、桑基；批次随时间留存用 Cohort | 漏斗有明确顺序与共同人群口径；桑基流量应可核对收支；Cohort 需要批次与观察期。独立类别不构成流程。 |
| 哪些因素解释总体变化 | 瀑布、增减贡献分解 | 起点 + 各项增减 = 终点，保留正负号与剩余项；统计相关性不能直接写成贡献或因果。 |
| 层级结构由谁贡献 | 矩形树图、层级构成图 | 需要真实父子关系及可加总的非负值；精确排名优先条形，面积不替代明细。 |
| 未来可能怎样，范围有多大 | 实际与预测折线、区间带 | 需要真实模型/来源、预测起点与区间定义；没有区间证据不画置信带。观察值、估计值与预测值可辨认。 |

需要联动时只选声明支持的绑定，并显式指定消费者。快照组件不能因设置 `datasetId` 就获得动态筛选。定制渲染可补充复杂形态，但保留其计算与交互边界，见 [组件渲染](component-html-generation.md)。

## 阅读层级与一致性

- 让首屏回答主问题，下一层解释变化，明细用于核对。为每个组件保留一个明确的分析用途；重复指标仅在不同上下文有实际价值时保留。
- 用尺寸和位置表达重要性。主图可更宽，相关小图共享基线与阅读顺序；不要给所有图同等视觉权重，也不要为填满网格添加无关图。
- 同类比较使用相同图型、类别顺序、颜色和可比坐标范围；不同页面的重复结构可帮助读者比较。形态差异应来自问题差异。
- 标题说明指标、对象或有证据的发现；时间范围和单位只放在必要位置。长定义进入详情，长解释进入正文，避免标题、图例、标签与 Tooltip 四处重复同一句话。
- 颜色先区分类别，再突出当前关注对象；同一实体跨图保持一致。用克制的中性色承载背景信息，不用无含义的渐变、阴影或装饰抢占数据注意力。

## 标题与指标卡

- KPI、图表、表格共用 14px、600 字重的组件标题。主数值独立缩放；调整卡片尺寸和列数时沿用组件默认标题和图表字阶。
- KPI 只显示标题、主数值、单位、比较值，以及图形所需的数值标签。禁止副标题、描述和解读段落。
- 指标定义、计算公式、来源和明细放在详情中；叙述分析使用独立文字组件。
- 图表副标题可选，只用于标题未表达的必要信息。卡片内容在可用空间中平衡上下留白。

## 颜色与图形

- 深海蓝用于主要数据；分类颜色表达类别，正负颜色表达变动方向。阈值、单位、精度和判定规则来自业务声明。
- 按比较、趋势、构成、分布或关系选图。预设、自由 ECharts 和 HTML 组件均可使用，声明方式见 [组件渲染](component-html-generation.md)。
- 图例、轴名称和数值标签留出各自空间。按内容和容器调整边距、标签位置与刻度，不使用一组固定几何参数覆盖所有图形。
- Tooltip 显示该点的实际数据和单位。浮层应显示在卡片裁剪区域之外。

## 操作与更新

- 已生效的筛选要在关闭下拉面板后仍能一眼辨认。用原生控件的激活样式突出所选项，并在筛选栏或表内显示当前值。需要点「应用」的控件只把已提交的值标记为生效。
- 点击散点、柱条等图形触发联动时，源图形持续高亮选中项，并适当弱化其余项。移开指针、关闭 Tooltip 或相关组件重新计算后仍保留高亮。清除条件后同步恢复图形样式和受影响组件。
- 常用筛选器能在可用宽度内排成一行时直接展示。窄屏按布局换行，单选、多选、默认值与作用范围沿用业务规则。
- 图表、表格操作位于标题区右侧，图标无外框线；窄卡片将次要动作收进菜单，保持单行。
- 无兼容类型时隐藏图表切换入口；无明细表时隐藏转表与 CSV 动作。
- 查询期间保留组件和已有内容。筛选、粒度及翻页只更新相关组件；减少动画偏好下关闭过渡。
- 图标复用 Lucide 和项目共享信息图标，交互控件提供名称与键盘焦点。

## 表格与布局

- 表头和单元格默认居中；同列使用一致的对齐方式与边距，数值使用等宽数字。
- 默认按最多 10 行计算表格高度，少于 10 行按实际内容收缩；分页与搜索作用于同一筛选范围。
- 宽表允许横向滚动。布局按阅读顺序、字段数量和容器宽度决定，模板见 [布局选型](layout_templates.md)。
- 金额、比例和精度沿用指标或列定义，单位不能因视觉调整发生变化。

## 交付前的设计复核

先核对源数据、口径与计算，再看呈现。按实际交付画布检查：主问题能否快速定位；比较对象和基线能否读懂；轴、图例和长类目是否拥挤；颜色含义是否一致；筛选生效和清除是否明确；明细是否可追溯。报告同时检查图注、来源与正文结论使用同一范围。分别记录声明检查和实际页面检查，不把工具成功等同于宿主视觉验收。

修正发现的具体问题后交付；不为追求图型数量、模板变化或装饰效果追加组件。
