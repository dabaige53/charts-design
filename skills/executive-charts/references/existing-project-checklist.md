# 接入已有项目

在已有页面中修改看板时，先确认数据来源、业务含义和保留的交互，再选择渲染入口。

## 确定范围

- 找到页面入口、构建命令、路由、认证和数据加载位置。
- 确认交付形式：Runtime 看板、导出网页，或现有框架中的组件。
- 列出需要保留的数据、单位、计算公式、筛选消费者、导出和批注能力。
- 沿用组件稳定 ID；业务内容的修改以用户要求为准。

## 映射组件

| 内容 | 接入要求 |
| --- | --- |
| KPI | 主值、单位和比较值绑定已定义指标；定义和解读进入详情 |
| 图表 | 根据需求选择预设、自由 ECharts 或 HTML；声明实际支持的动作 |
| 筛选 | 单选、多选、日期等条件绑定明确字段和消费者 |
| 表格 | 列键、标题、单位、排序与分页使用同一数据范围 |
| 详情 | 业务定义、公式、来源和明细对应当前组件与筛选 |

声明与渲染入口见 [组件渲染](component-html-generation.md)；CLI 校验见 [工作区命令](dashboard-workspace.md)。

## 集成与检查

1. 明确页面布局、数据查询、筛选状态和组件生命周期的负责模块。
2. 接通一个完整业务区域，检查原始数值、过滤结果及单位，再处理其余区域。
3. 更新时保留图表实例，卸载时清理监听和资源，隔离不同看板的状态。
4. 应用 [设计规范](design_standards.md)，检查标题、工具栏、表格对齐以及窄容器溢出。
5. 按 [项目测试规则](../../../docs/operations/testing.md) 检查本次改变的行为；交付说明尚未接通的能力。
