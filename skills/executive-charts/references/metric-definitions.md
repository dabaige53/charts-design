# 指标定义与统计口径写作规范

适用于 KPI、图表、表格及分析报告中的指标说明。业务定义由数据来源和已确认的业务规则编写；页面筛选和计算配置负责提供实际计算信息。两者必须一致。

## 各部分分别写什么

| 内容 | 必须回答的问题 | 写法 |
| --- | --- | --- |
| 业务说明 | 这张图用于观察或比较什么？ | 用 1–2 句说明分析对象与用途，不重复标题，不预设结论。 |
| 业务定义 | 指标统计什么？数值代表什么？ | 用 1–3 句中文说明统计对象、统计范围及结果含义。定义中有“净”“纯”“有效”“活跃”等限定词时，必须解释其业务边界。 |
| 统计范围 | 哪些记录进入计算？ | 明确时间字段及日期边界、业务对象、组织/地域范围、记录粒度、纳入条件和排除条件。当前筛选值由页面展示；固定规则由作者说明。 |
| 计算公式 | 如何得到这个数？ | 使用中文指标名称写公式，明确分子、分母、求和/计数/平均/去重及计算顺序。比例要说明先汇总后相除还是逐行计算后平均。 |
| 单位与展示 | 数值按什么量纲阅读？ | 明确单位、缩放、百分比和小数位。比例原值与百分比显示不可混用。 |
| 判定规则 | 什么条件下判定为达标、异常或变化？ | 写清比较对象、期间、阈值、方向和阈值依据。没有已确认阈值时，不添加“越高越好”“行业领先”“享有激励”等结论。 |
| 异常与边界 | 缺失、零值、负数和重复记录如何处理？ | 按实际计算行为说明。缺失不能写成零；分母为零不能写成 0%；计数不能写成去重人数。 |
| 查看语义、SQL 与来源 | 如何复核定义和计算？ | 展示实际字段、数据集、聚合表达式、分组、筛选、换算、已记录 SQL 和参数；不执行或编造 SQL。 |

“业务定义”与“计算公式”应让业务读者直接理解。“查看语义”承担字段和 SQL 层面的复核，不用 SQL 函数代替业务定义。

## 信息不足时

- 从用户说明、字段字典、查询条件或已确认的业务规则中获取依据。只有字段名和标题时，不能补写会计确认、税费、退款、去重、归属或绩效政策。
- 明确写出具体待确认项，例如“退款按原销售期冲减还是退款发生期冲减，待业务确认”。不要用“遵循统一业务口径”“标准业务核算公式”等空话填充。
- 未确认的定义保持 `status: unverified`；不能因文案写完整或程序校验通过就改为 `reviewed`。
- 新建交付物必须补齐影响解释的业务边界；已有交付物保留已确认内容，列出缺口，不擅自覆盖用户定义。
- 演示来源标识与业务定义分开。业务定义中不写“合成数据求和”“仅用于演示”等来源备注；也不删除来源记录本身的真实性标识。

## 业务定义示例

### 营业收入

> 所选月份和区域内，收入记录的金额合计，用于比较各期与各区域的收入规模。

中文公式：营业收入合计。是否含税、收入确认时间和退款冲减方式，需要来源说明后才能补入定义。

### 预算达成率

> 所选月份和区域内，营业收入占同期预算收入的比例，反映当前收入相对于预算目标的完成程度。

中文公式：营业收入合计 ÷ 同期预算收入合计，按百分比显示。计算必须先汇总后相除；不能平均各条记录的达成率。只有预算确为同一期间、范围和量纲时，才能使用此定义。

### 收益变动率

仅适用于已确认 `yieldDelta = 本期收入 − 基期收入`、`yieldBase = 基期收入` 的数据：

> 所选月份和区域内，收入相对基期金额的增减幅度。正值表示收入增加，负值表示收入减少。

中文公式：收入增量合计 ÷ 基期收入合计，按百分比显示。不能自行称为“同比”或“环比”；须先明确基期对应上年同期还是上一期。

### 纯中转市场净销售

不能只解释为“纯中转市场净销售额”，也不能直接假定为“销售额减退款”。写定义之前，至少确认：

1. “市场”按什么划分：出发地—目的地、航段、渠道，还是其他维度？
2. “纯中转”的纳入条件是什么？混合行程和多次中转如何归类？
3. “销售”指金额、订单数、票数还是其他数量？
4. “净”扣除什么：退款、税费、佣金、折扣或其他项目？
5. 按销售日期、出票日期还是实际履行日期归属？退款归属哪个期间？
6. 重复、取消、改签及负数记录如何处理？

缺少这些依据时，具体列出待确认项，不能生成一段看似完整的业务定义。

## 配置位置与交付检查

Runtime 的业务定义写入 `manifest.metrics[id].definition`；计算依据仍由 `aggregation`、`field` 或 `numerator`/`denominator` 指定。使用完整中文句子记录已确认的范围和边界，不添加未声明的指标字段。

原版组件使用 `config.explanation.overview`、`type`、`period`、`comparison`、`structure` 和 `metrics[]`；每个指标的 `name`、`definition`、`formula`、`rule` 分别承担名称、业务定义、中文公式和已确认的判定规则。更长的统计范围或边界可写入 `notes` 或 `limitations`，页面直接展开。

交付前逐项检查：定义能独立阅读；限定词都有解释；公式对应实际配置；比例汇总顺序正确；单位与时间范围一致；未虚构纳入/排除项、去重或判定规则；SQL 和来源可复核；缺失依据明确列出。

界面正文只包含业务内容与可复核的数据记录。不得加入“正式页面将展示”“仅用于版式演示”“参数将跟随筛选”等制作过程或未来实现说明。统计周期和对比基准使用可换行的字段行，长段文字不塞入标签。组件 SQL 与数据来源 SQL 分别在 SQL 与来源区展示，不放入补充说明。
