# 部署样例与性能验收

## 确认目标和访问范围

按[MCP 交付](mcp-delivery.md)定位实际服务、后端、项目及存储格式。分别记录用户要打开的入口（静态站、在线只读或编辑）和授权范围。沿交付入口确认它读取哪份文档、哪种索引和数据文件。共用一个前端或查询 Worker 的页面也可能读取不同资产。

按约定的账号或 token 实测页面、选项和底层数据的访问范围。编辑分享核对允许的页面、有效期和进入编辑的能力。业务筛选用于选择数据；访问范围由服务端授权落实。

## 先让一个真实页面跑通

选择有代表性的数据量、常用筛选以及目标端的真实交互。在批量导入前，检查目标项目实际采用的读取分区字段。按常用查询、数据量和访问边界选择分区粒度；小数据可整份读取。上传分块用于传输与续传，存储分区决定查询时能跳过哪些数据，两者分别验证。

在交付地址用冷缓存打开样例，记录首屏到数据可读、首次展开筛选到选项可用、切换范围到图表和正文更新的时间。再重复操作检查缓存复用。用浏览器网络记录核对请求数、传输字节、最长等待以及实际命中的数据分区。独立检查选项索引是否逐数据集串行读取；针对实测瓶颈选择索引复用、批量读取或分区方案，再重测同一操作。

与原站或预览比较时保持相同数据范围、角色和缓存条件，并记明宿主与读取路径。以项目约定或同条件基线判断是否可接受。记录样例规模与全量差异，交付后在最终入口复测。

## 估算并恢复批量发布

按内容、粒度、口径和授权范围复用已核实的不可变数据。合并来源时重放默认、切换和清空筛选，核对基期、分母与明细边界。对照目标库存，用剩余数据的实际压缩体积估算净上传量。

按连接版本支持的批量大小、并发和续传方式运行样例。用实测值分别估算传输、服务端校验入库、保存页面与交付验收的耗时，注明可并行的阶段和仍未知的部分。中断后以服务端回执核对已入库版本和已收分块，再续传。以保存的文档和实际可读的数据版本确认完成。
